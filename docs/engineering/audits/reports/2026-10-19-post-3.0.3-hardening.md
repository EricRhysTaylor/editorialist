# Post-3.0.3 hardening pass — 2026-10-19

## Scope

Reviewed all changes after the latest published release, `3.0.3` (published 2026-10-18), through `95442ed`: five commits, 37 changed files. The local release tag resolves to `0a346e4`. The pass covered explicit manuscript targeting, migration, imports, folder/name reassociation, registry and review-history persistence, modal integration, and engagement refresh behavior, including their callers and existing tests.

## Corrected findings

| Area | Failure | Correction |
| --- | --- | --- |
| Active-note imports | A Markdown view could navigate during validation, causing feedback to be appended or stamped in a different note. | Recheck the view's file immediately before editing its buffer. |
| Import transaction | A target change during the final write could escape validation. | Validate after the final write so the existing compare-and-swap rollback runs. |
| Inventory concurrency | An older scan could replace the inventory for a newer selection. | Invalidate pending scans on target changes and registry loads; require the scan generation and resolved scope to remain current. |
| Batch retention | Narrowing the target retained note records but dropped their batch presence, making live rounds appear cleaned. | Preserve batch presence for retained, unscanned records. |
| Reconnect rollback | Unsaved edits in an open Editorialism could be overwritten while rolling back metadata. | Flush open editors before rollback's content comparison; retain changed text when the comparison fails. |
| Observed renames | An untracked pinned note, or its parent folder, could become disconnected. Plain-note decisions, queries, reviewer signals and progress could keep old path keys. | Follow the selected path even without prior inventory; remap path keys and preflight collisions before changing live state. Surface conflicts while retaining both histories. |
| RT title ownership | Renaming an RT book folder could replace its title with the folder basename and break name-based associations. | Read the loaded RT book title for active and inactive books when following RT; preserve standalone naming independence. |
| Engagement refresh | Requests arriving during a read were dropped; switching targets during a read could retain the previous engagement. | Queue another refresh, discard the previous manuscript's presentation when scope changes, and use the view's owning document for input-focus protection. |
| Cleanup | A target change during a multi-note cleanup could allow later writes; blocked cleanup was counted as successful. | Check membership before each write and report skipped/partial cleanup truthfully. |
| Guided sweeps | A saved sweep could start, advance or finish outside the selected manuscript. | Check its note membership before continuing the workflow and opening review notes. |
| Path dictionaries | Special folder names such as `__proto__` could lose aliases or resolve inherited properties. | Use a null-prototype remapping dictionary and own-property alias lookups. |
| Dialog requests | Inputs could change while a reconnect preview or target save was running. | Disable controls while busy and detach request/preview snapshots from editable state. |

Also removed two unnecessary assertions and simplified the exclusion-path placeholder. The official report-only lint now has zero errors and one existing settings-search API advisory.

Inspected the empty review state for a plain pinned note. Screenshots and rename-result evidence are retained outside the public repository under the dated hardening QA run.
- Restored QA data, workspace and appearance settings and removed this pass's disposable note fixture. No author manuscript fixtures were created or modified.

## Limits

Async target changes, write failures, rollback with unsaved edits, history collisions and stale scan completion were exercised deterministically in tests; they were not fault-injected into the native application. Busy dialog frames and popout-window focus were code-reviewed but not separately captured natively. This pass does not claim atomicity across every guided-workflow await or protection against unrelated external writers. The full settings-search migration remains separate work. No release or version bump is part of this delivery.
